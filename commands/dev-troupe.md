# DevTroupe 开发剧团：主控做导演，五岗按需上场

把代码、测试和真实结果作为交付依据。默认由主控直接完成工作，只有能明显减少成本或增加独立判断时才调用子代理。

## 本次任务

$ARGUMENTS

如果本次任务为空，先请用户给出具体开发目标，不自行假设需求。

## 快速开始

先执行下面由 ZCode 交给 Bash 的动态命令；它会打印本次安装的 CLI 绝对路径并运行本地检查：

!`printf 'TROUPE_CLI=%s\n' "${CLAUDE_PLUGIN_ROOT}/bin/troupe.mjs"; node "${CLAUDE_PLUGIN_ROOT}/bin/troupe.mjs" doctor`

后续示例中的 `<TROUPE_CLI>` 必须替换为上方实际输出的 CLI 绝对路径。不要假设后续 Bash 环境中存在插件根目录变量。

首次使用或从旧版迁移时：

```bash
node "<TROUPE_CLI>" init
# 旧配置不在默认位置时：
node "<TROUPE_CLI>" init --from /path/to/legacy/ai-dev-org
node "<TROUPE_CLI>" sync
```

`init` 不覆盖已有配置。空配置需要按插件 README 添加模型槽位。`sync` 后新建会话，宿主才会加载新的代理档案。

## 默认流程

1. **理解**：确认用户目标、相关代码和项目约定；小任务直接做，不先写计划文书。
2. **实现**：主控直接修改，或把边界清楚的一块工作交给一个 executor。
3. **验证**：运行与变更相关的测试和检查，查看最终 diff；失败就修复或如实报告。
4. **交付**：说明改动和实测结果。未提交事项使用项目已有的 issue/待办，不另建账本。

没有固定双审、任务书审核、实证裁决、强制交接、逐批复盘或返工轮数要求。

## 可选工作流与批次快照

小任务仍由主控直接完成，不创建批次文件。多批任务可先查看并展开可选模板：

```bash
node "<TROUPE_CLI>" workflow list
node "<TROUPE_CLI>" workflow show feature
node "<TROUPE_CLI>" workflow plan feature --json
```

`plan` 只做 dry-run，不调用 Agent、不修改文件。主控可按需把输出保存为当前项目的 `.zcode/dev-troupe.batch.json`，作为本次任务的队列快照；不是每个任务都需要它，也不自动创建。

- `controller` 批次由主控直接完成，其他角色按现有 `pick/route` 方式派发。
- 批次状态只使用 `pending/active/done/blocked/skipped`。每批结束后，根据真实结果更新 `currentBatch`、状态及该批 `result`；角色末尾的契约 JSON 是后续批次输入。
- 可选节点由主控判断并显式标记 `skipped`；不得静默跳过必需节点。需要改变范围或依赖时，先修改计划再执行。
- 写批次默认串行，独立只读批次才可并行；主控负责返工、模型回退和用户确认，快照不会自动推进任何任务。
- 新会话恢复时先读取快照，再核对实际代码、测试和 git diff；不得仅凭快照中的 `done` 继续。视觉批次还必须核对真实图像。
- 快照不是质量账本、自动状态机、后台队列或永久交接件。任务结束后按项目已有方式处理，不形成平行账本。

## 何时调用角色

| 角色 | 使用时机 | 不必使用的情况 |
| --- | --- | --- |
| research | 需要独立检索代码、文档或外部资料 | 已知文件中的单点事实 |
| planner | 多方案架构取舍、跨模块或高风险路线 | 局部修复、明确实现 |
| executor | 独立且边界清楚的实现块 | 主控可立即完成的小改动 |
| reviewer | 高风险逻辑、安全/数据迁移、争议结论或用户要求 | 每次普通修改的固定复审 |
| vision | 已有渲染图且需要视觉验收 | 只有代码、没有图像 |

普通任务最多调用一个 reviewer。确有两个独立问题需要不同专家时，可以并行只读派发；写同一文件或共享状态的任务串行。

## 路由与派发

```bash
# 查看全部角色和顺序
node "<TROUPE_CLI>" list
# 查看一个角色的回退顺序
node "<TROUPE_CLI>" route executor --json
# 只取当前首选代理名
node "<TROUPE_CLI>" pick executor
```

将 `pick` 的输出用作 Agent 工具的 `subagent_type`。派发文本直接说明目标、范围、相关路径和验收方式。角色返回的可读正文和末尾契约 JSON 可作为后续批次输入；禁止旧式 LEDGER、账本或其他平行机读尾栏。

首选代理因实际限流或不可用而失败时，按 `route` 的下一项继续；配置错误先修配置，不盲目重试。模型、供应商和档位以生成档案为准，不假装一次调用能强制切换宿主模型。

## 配置面板

```bash
node "<TROUPE_CLI>" panel
```

面板仅监听 `127.0.0.1`，默认端口 8787，不自动打开浏览器。需要由 agent 启动时使用后台进程，并返回本地 URL。面板用于调整五岗顺序、思考档位和重新生成代理；不展示账本或批次状态。

## 保留的边界

- 只读角色不写实现；实现者不自行审核并宣布独立通过。
- 并行任务必须相互独立，子代理不再派发子代理。
- 不用删除测试、降低断言或隐藏失败来制造绿色结果。
- 产品方向、需求冲突、额外费用、凭据、破坏性操作和对外发布仍由用户决定。
- 不创建 org-ledger、任务书证据包、RESIDUALS、HANDOFF 或固定格式审计报告；可选的 `dev-troupe.batch.json` 仅是当前任务计划快照，不升级为平行账本。

## 开发插件自身

```bash
npm test
npm run verify
```

插件源码的测试和 manifest 校验是唯一的常规门禁；不再运行旧版 regression、术语棘轮或文档数字墙。
