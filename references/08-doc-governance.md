## 2. 多项目归并指针化手册（四步）

1. **盘点映射**：项目文档群逐件对照 §1 寻址表，产出**全量映射表**——
   漏一件=中间态双源。盘点范围=项目根全部 .md 群+docs 子树（以开工日
   实扫为准，快照清单仅为索引）。**件级四态+两类登记**：
   - **承接**=项目真相源保留（硬规则/环境/契约类事实）；
   - **指针化**=整件为通用原理复述 → 改指针+一行项目差异注记；
   - **拆分**=件内混装（项目特有段+通用复述段，宪法即典型）→ 段级
     处置：特有段承接、复述段指针化；
   - **废弃**=过时件 → 归档三件套；
   - **登记·历史归档件**=已入档过程记录 → 原样登记免处置（§3 禁止项）；
   - **登记·配置件**（mkdocs.yml 等）=不入映射表，仅登记导航/引用变更。
2. **裁决**：四态选择属用户裁决面（裁决权限三分法负面清单）——代理
   只起草映射表汇报，**禁代裁、禁裁决前动正文**（项目阶段预授权明列动作
   除外，预授权须逐项列明于任务书）。
3. **一次性执行**：裁决后在**单一提交**内完成全部处置（禁分批渐进
   ——中间态=双源最长暴露窗）；有 grep 门禁的项目加装「指针化对照」
   检查（正文中与技能 references 重复的通用原理段=红，白名单登记例外；
   豁免须汇报理由入 org-delta）。
4. **机检兜底**：已插 ORG-SEG 段的项目必跑预算自检；结项核对基线
   HEAD 与历史件哈希锚（见 §3）。

**词汇差异处理**：项目与技能的术语差=新增**双向词汇映射表**挂宪法
头部、置于 **ORG-SEG 标记段之外**，历史原文
零改动——映射表是桥，不是改写令。

## 3. 历史件禁改写

- **适用面**：一切已成档的过程记录——旧交接书/briefs/审计档/项目阶段报告/
  已并入 git 历史的文档/commit message。
- **理由**：它们是审计链与决策溯源的载体（P7/D2）；改写比删除更糟
  ——删除在 git 历史仍可考，改写制造「当时就是这么说的」伪证。
- **机检形态**（防 amend/rebase 伪证——git diff 对改写历史盲）：批次
  开工记录基线 `git rev-parse HEAD`+关键历史件 sha256 锚；结项核对
  HEAD 祖先链形未变+锚定哈希零变动。
- **唯一合法动作**：追加（新文件/新段标注日期）或归档；发现历史件
  有错 → 新增勘误件引用原 file:line，**禁原地修改**。
- 新写文档引用历史词汇时用映射表括注（如「闸（=门审授权）」）。

## 4. 文档腐化体检（触发式+定期）

- **触发式**：技能 references 版本升级或项目宪法修订后，对照 §1 寻址表
  扫指针化漂移——被指文件还在吗/内容还匹配吗/新增了正文抄写吗。
- **定期**：每项目阶段结项随教训回流查四项——①台账引用的基线数字与宪法
  口径一致且指针零死链 ②双源复发扫描（新写的通用原理段落）③stale
  文档（连续两项目阶段未引用且内容过时=候选，入映射表）④预算自检 PASS。
- **裁决通道**：体检产出的候选件**随项目阶段结项一并攒批汇报**（复用
  映射表裁决通道，不另设）；体检结论一行入项目账本（`event=doc-health`）。

## 6. 产出入仓面纪律

**适用面**：凡将进入**项目仓库 git 跟踪面**的工件——源码注释与字符串、
md/文档、测试与快照、审包审出件、commit message、**文件命名**。

**规则**（违者=项目仓门禁红或人工对账拦截）：
1. 文件名与内容**零外部模型代号、零 AI 指称**（「由 AI 撰写」「AI
   审阅」类署名/过程措辞）——词表**单源=项目仓门禁脚本**（以项目宪法
   声明为准）。叙述措辞中性化先例：
   「本段由 AI 撰写」→「本段由撰写管线生成」。
2. **commit message 同面**——模型名/岗名不入提交说明（git 历史虽
   属自留历史区，但随仓流转即污染面）。
3. **派发工件命名弃源别名后缀**——`*-<源别名>-out.md` 类命名只准
   用于仓外过程区；入仓件用中性名（票号/日期/序号）。
4. **审档归宿收紧（修订 §5 惯例）**：§5「起草方项目仓内 scripts/
   audits/」自本节起仅限**已过规则 1/3 的中性化件**；审包/审出件
   默认归宿=**项目仓外历史区**（各项目归档目录）。
   反例存照：曾发生审包入库带模型别名（md 面无门禁
   直通——正是本节起因）。
5. 项目仓白名单例外（如 WaterPrint AGENTS.md、治理目录）以**各仓
   门禁配置**为准，本节不另开豁免。

**边界（与 §1 判例分工）**：本技能与治理文档自身的「安排性提及」
（drafter/auditor 分工链、教训库事件叙述）**不属污染面**——§1 判例
管辖技能文档怎么写，本节管辖**项目仓提交面**产出什么。两道闸各管各面。

**机检执法面**：项目仓门禁（规则 1 指针）——技能侧不重复造扫描器；
项目仓 md 面扩栏=另立批次（登记残留，见 RESIDUALS）。

## 7. 已审面修改随批重过

任何已过对抗审的面（文档/代码/配置/角色卡/DoD/golden 冻结副本）再次被
修改时，**该面随所在批次重新过审**：向首审岗呈**改后 diff**（非全量重审），
首审结论沿原档追加。golden 类冻结副本的重生成（`--update-golden`）视为
已审面修改的机器形态，须随工作单元提交并在修订记登记（冻结纪律先例）。

本节为其正式登记处。

## 8. 文档模板治理

本节为文档模板治理四项口径（c-1~c-4）；配套承载=

### 8.1 变更锚字段（c-1）

- 新文档头部元信息引块规定四字段：**状态／权威／替代／变更锚**（末字段）。
- 「变更锚」记最近变更批次与账本行（批次号＋账本行号，与「替代」同为单字段一行）。
- 新文档要求末字段；存量文档不回填（禁逐件补写旧文）。

### 8.2 词汇前置准入（c-2）

- 新领域名词先落术语表（references/00）并经用户认可后方可入正文使用。
- 范围限领域名词，普通行文词不在此列（不拦行文）。

### 8.3 摘要＋详述结构（c-3）

- 新文档分两部分：**摘要段**（讲来龙去脉与业务逻辑）＋**详述段**。
- 交接件与结项件自本批起用此结构；存量件不回改（与 c-1 存量不回填同理）。
- 正文不得出现按读者类型区分的标注字样（如标注某段面向人类读者、某段
  面向机器读者一类表述）。

### 8.4 新项目 evidence 骨架（c-4）

- 新项目 evidence/ 下三子目录：**handoffs/**（交接件）、**close/**（结项件）、
  **session-logs/**（会话记录）。
- 本仓不铺设；骨架承载=`templates/evidence-skeleton.md`；init-defenses
  脚手架铺设留后续批（本批不改脚本）。

### 8.6 RESIDUALS 权威段与扫描闭包（B6 文档生成批）

- **唯一权威**：RESIDUALS.md 的 `residuals-json` 标记对之间为唯一权威（schema=residuals/v1，每条恰八键 id/status/owner/trigger/evidence/created_at/phenomenon/description，id 字典序 canonical 化）；旧表整块冻结移入历史小节（sha256 锚＋「冻结·非权威」），仅供对账；禁止双写——冻结表外不得存在同形登记行，新登记只走 JSON 八键。
- **扫描禁令**：RESIDUALS 全文禁 term-scan off/on 开关标记；权威 JSON 段禁 Markdown 围栏（非围栏字符串才可被词面与零代号扫描；围栏会被 check-terms 跳过，故由 residuals-check 拦截——双闸缺一不可）。解析器挂 `--check`。
- **账本校验复用**：gen-commit-summary 只逐行定位 runId（恰一行才继续），不声明该行通过 schema 校验；账本校验仍只跑 B1 `ledger-migrate.mjs --verify` 与既有 R4，不另建第二套写入或校验链。
- **回访条件**：Conventional 试点三行与锁定面例外第四行——连续两批试点无返工笔形态问题后由主控回访是否升格；升格回访时须复核锁定面第四行试点例外。
