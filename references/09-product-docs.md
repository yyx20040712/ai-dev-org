# 09 · 产品文档编制面（需求规格/用户手册/API 文档）

> 定位：补齐「两类文档不在编制内」的前置缺口之一——产品面文档此前
> 无岗位无生命周期（优化战役 2026-09-10 前提③）。本件给出事实分层、
> 生命周期挂钩与三件模板；编制承载=**tech-writer 子模式挂主控**（同
> PM 子模式先例——07 §2「子模式承载，不设独立转述岗」，不新增岗位
> 编制、不入角色注册表）。多人团队化边界不在本件（=SKILL.md 团队化
> 边界段，只显式化不实现）。

## 1. 事实分层（并入 08 §1 寻址表「产品文档」行，本节为细则）

| 文档类 | 唯一真相源 | 生成规则 | 禁止出现处 |
|---|---|---|---|
| 需求规格 | `docs/spec/`（五问产物，见 §3.1） | 手写（intake 五问落盘=立案前置物） | 交接书正文复述（交接书只留指针） |
| 用户手册 | `docs/manual/` | 手写骨架+截图位（见 §3.2） | 与实现细节耦合（每个 UI 像素级描述=维护地狱） |
| API 文档 | 代码注解→生成物 | **锚定生成器**（OpenAPI 类）：手写只做注解与概述，路由/参数/类型由工具生成 | 手抄端点清单（与代码双源必漂移） |
| 变更日志/发布说明 | `CHANGELOG.md` | 每战役收官追加（§2） | 事后补写（记忆漂移=失实） |

## 2. 生命周期（与战役节奏挂钩——不设独立周期）

- **立项时**：intake 五问（07 §2 PM 动作 1）的产物直接落 `docs/spec/`
  ——需求规格不是「以后补的文档」，是立案前置物。
- **每战役收官即回写**（同 02 §3「收官即回写」条款）：功能面变化
  →手册对应节+CHANGELOG 追加；契约面变化→API 注解重生成。禁止
  「事后补文档窗口」——攒批补写=失实之源。
- **腐化体检**：并入 08 §4 触发式体检——手册引用的界面/入口还在吗、
  生成器输出与代码一致吗（生成物过期=CI 应红）。
- **裁决通道**：文档取舍（写不写/写多细）=用户裁决面候选，随战役
  收口攒批呈报（复用 08 §4 通道）。

## 3. 模板三件（骨架级——复制后按项目裁剪）

### 3.1 需求规格（intake 五问产物）

```markdown
# 需求规格：{{功能名}}（{{日期}}，状态：已裁决/草稿）
①目标：一句话——给谁解决什么问题
②范围边界：做什么 / 明确不做什么（负面清单）
③硬约束：受锁面/安全红线/依赖预算/视觉决策归属（谁裁决）
④验收标准：可机检形态优先（verify 用例/CI gate/DOM 断言）
⑤时间盒与额度预算：{{box}}；稀缺源投放={{确认/不投}}
——用户原始请求逐字附后（转译表见台账 Ruling 行）
```

### 3.2 用户手册骨架

```markdown
# {{产品名}} 用户手册
## 是什么/给谁（一段，与宪法「项目一句话」同源不抄写）
## 快速上手（安装→首次配置→第一个任务，≤10 步）
## 功能逐节（每功能=入口→步骤→预期结果→常见问题）
## 常见问题（FAQ，从支持对话/教训库回流）
（截图位标记 {{screenshot:场景名}}——发布前统一补拍，禁散落维护）
```

### 3.3 API 文档（锚定生成物）

```markdown
# {{产品名}} API 概述（手写节，≤1 屏）
- 鉴权/版本策略/错误码总表（手写）
- 端点明细：**由生成器产出**（命令：{{项目生成命令}}，CI 校验
  生成物与代码同步——不同步=红）
（手抄端点表=禁止——与代码双源必漂移，见 §1 表）
```

## 4. tech-writer 子模式（挂主控——动作清单）

同 PM 先例（07 §2）：主控身份叠加「tech-writer 子模式」，不设独立
岗位（编制不变=8 岗），文档产出仍走「起草→门审」通道（涉仓库文件
走轻量双审，同 02 §3 文档/制度批）。

1. **触发**：intake 五问落盘时（需求规格）；战役收官回写时（手册/
   CHANGELOG）；契约变更时（API 注解+再生成）。
2. **动作**：按 §3 模板起草→核对实现面事实（读代码/测试，禁凭记忆
   写行为）→生成物跑生成命令核同步→呈报（文档取舍候选随收口攒批）。
3. **禁令**：禁在文档中发明未实现的行为（=虚假承诺）；禁手抄生成物；
   禁跳过「与实现面核对」直接交付。
