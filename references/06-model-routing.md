### 1.1 意图口径路由默认表

| 岗位 | 默认模型 | 理由 |
|---|---|---|
| 编排者 | 主力档（实配=org-config roles 编排者行） | 拆解/裁决/终裁亲验是判断力密集环节，不降档 |

| 审核岗（auditor-readonly） | deepseek | 不同模型族挑刺——审计面放行条款照用 |

### 1.2 三段通道（路线级设计）

架构设计/技术选型/跨模块重构路线/性能优化方案等路线级决策走三段通道：
`drafter` 岗拟定设计书（候选≥2＋权衡）→ `auditor-readonly` 对抗审核
（只挑错不改写）→ 主控终裁＋指挥实现；单函数级局部优化不走此通道（主控直裁）。

- **链条四步**：
  0. **社区实践调研前置**：较大模块的路线选择，
     主控派发前先做社区实践调研——社区内知名项目/权威团队对同类模块的
     选型与结论（可用 WebSearch），产出「候选路线×各家选择×理由摘录」清单
     随任务包供拟定方参考（不要求穷尽）；调研来源入设计书附录可追溯。
  1. **drafter 岗（Kimi 族）拟定设计书**：候选路线≥2＋逐项权衡（复杂度/
     风险/迁移成本/额度成本）；耗尽/限流按 §4 状态机切换承载源（任务书与
     DoD 不放宽）；双源皆尽→主控自拟并记「拟定同源」待补登记事件。
  2. **auditor-readonly（deepseek）对抗审核**：只挑错不改写（改写=回到
     拟定方）；审核面=风险点/隐性成本/被遗漏的第三方案/与现有防线的冲突；
     审计面放行条款照用。
  3. **主控（主力档）终裁＋指挥实现**：唯一终裁权——合并拟定与审核意见定案
     （负面清单/新依赖/规格冲突仍留用户），随后按管道派发实现岗落地。
- **利益分离**：拟定方不终裁、审核岗不改写、终裁不跳审自裁；Kimi 与 deepseek
  不直接承担实现。
- **入账**：三件产物（设计书/审核意见/终裁理由）为决策原文入台账（ADR 级
  决策走 ADR 文件）；成本按模型×供应商×套餐分列。
- **与两道审查的关系**：设计阶段的对抗前移——实现完成后的代码审查岗/
  实证裁决岗照走，方案过三段通道不免实现审计。
- **实证锚点**：双源复审实战验证不同模型族
  对抗有效性——Kimi 抓到 deepseek 漏判的 3 个 B 级。

## 2. 三条设计铁律

1. **单一调用者**：一切模型/子代理派发只出自主控，显式指定机型+供应商+
   思考等级，禁静默继承默认（缺省继承=最贵档静默浪费）。「显式指定」
   合法形态三枚举：①外部
   派发器 CLI 参数；②frontmatter model 绑定（代理档案即显式——绑定岗免
   待补登记行，§6 补遗）；③随宿主形态（意图档位声明+session:host-tier
   待补登记行=E3 记账，属显式选择的合法降档，非静默继承）。
2. **实现与审查分离**：实现者不审查、审查者不实现；代码审查（岗）只见自包含
   diff 审计包（简报+完整 diff 内联+验证摘要），零仓库接触。
3. **不同模型族对抗**：审查者与实现者尽量异源（同源记待补登记）——稀缺额度
   只买「不同模型族对抗」这一件事。

## 3. 额度经济学（投放面原则；具体数字与禁止项看 org-config）

- 稀缺源（如企业版小额度档）只投两处：**路线级设计拟定**＋**代码审查岗
  兜底承载**。kimi 现役承载源配额充裕（用户申报≈主力之半，事实落位=
  org-config 本机件 note）——稀缺投放前提对其失效，投放面=代码审查岗常设＋
  路线级拟定＋前端任务设计稿拟定（文本形态；派发显式指定充裕承载源、不盲走
  链首真稀缺源）。必保面=受锁面/安全面/跨模块接缝/数据批/迁移/返工第二轮起/
  新依赖引入；可省面=≤3 文件小批/纯文档批/工程攒批非 CI 件——仅命中分级强制检查
  定义（小批/单点配置批）者方走单审减档、未命中默认全对抗位；工程攒批虽列
  可省面，仍按复合批并集取对抗位（并集规则单源=SKILL.md 派发前自检节）；
  构成与降档通道单源=SKILL.md 派发前自检节的分级规则段（原「降同源=配给内
  降级」口径已废——与 02 旧 §8 配给节同批处置）；历次岗位实例调整的逐字
  原文=当日账本 ruling 行。
- 套餐外按量源**分面放行**：实现面禁用；审计面
  放行（兜底层＋实证裁决岗不同模型族承载位），用量流水账可指认。
- 体验套餐（易逝额度）发现即优先消费：同档位先烧体验再烧主力；多模态任务
  默认低档体验位；判断力密集环节不降档；体验优先仅适用于体验套餐能力覆盖
  得住的环节；耗尽回落正式套餐不记切换承载源事件。
  开工盘点：管道步骤 2 配置自查一并盘点套餐池（正式＋体验逐项记档位/时效/
  剩余量/能力覆盖）。无体验套餐的多模态任务走快档主力（不占主力/Kimi 额度）；
  涉及关键裁决的多模态证据仍由实证裁决岗亲验复核；会话内子代理语境下套餐
  路由＝意图声明（环境限制记账与宿主图像通道配置口径=06 §6）。入账：成本按
  模型×供应商×套餐分列——体验额度烧在哪同样必须能指认。

## 4. 承载源切换状态机（主源耗尽换备源）

```
主源
 → 耗尽/限流/配额错 → 备源（任务书与 DoD 不放宽；事件=switch 入账）
 → 链内递进至兜底审计源（套餐外计价，事件=switch）
 → 全源尽 → 记 exhaust+「同源审计欠账」回退只读审子代理
    下一关键批优先补还不同模型族审计；（连续两个关键批未补还异构审计 → 升级用户裁决）
```

- 承载切换/待补登记/用量事件逐件入 `model-routing-log.jsonl`（派发器自动）
  与项目账本 `.zcode/org-ledger.jsonl`；审计报告头标注 [routing] 行。
- 退避：429/5xx/网络错指数退避 3 次后切换承载源；400/401/404（配置级错误）
  不退避立即切换承载源；403=额度族但**不退避**（立即切换承载源——与 429 仅差省退避，
  处置面同额度类=§6 补遗二「读进度落盘→派另一源继任」；log-triage 分诊同口径
  「配额限流(429/403)」，v2.0.1 修复批 L4 对齐）；末次守卫=抛真实状态码
  并落 switch 事件。
- 主备源同端点不同配额的形态（第二配额备源）与异供应商备源形态均
  由 org-config providers 描述，状态机不区分对待。
- **承载切换注记**：「派发/切换承载源」承载=绑定岗切换（主控改派另一绑定岗，
  按矩阵回退序递进=备用位/第三备用位启用条件照 07 §1），switch/exhaust 事件
  由主控补记账本（02 §9 单源）。
- **payg 显式告警**：链首源或承载切换目标为
  `billing:"payg"`（套餐外按量）时，派发器 stderr 显式 `[payg]` 告警
  ——承载切换不放宽任务书与 DoD（本节铁律），但费用面必须留痕不静默。
  〔现役承载=主控派发前核对绑定岗源 billing，payg 源承载岗（如 ops-auditor）
  派发即账本行标注+成本按「模型×供应商×套餐」分列（本件 §3；
  账本行 schema=02 §9），费用留痕义务不失效〕

### 5.7 传输层与超时（代码审查（岗）多轮排障+本机双臂探针实证）

**B5 流式化**：请求侧加 `stream:true`（openai 形
并配 `stream_options.include_usage`）——首字节早达根治网关非流式窗口 504 族
（配置位=org-config `vision_channels.<ch>.stream`——glm-look 消费；
dispatch_request 分区已随派发器删除〔清理批次〕，真窗异常可置 false 配置回退零代码变更）；响应侧 SSE/JSON 双形态解析
（org-config `parseSseText`+双形态收割器——产出与非流式**同构**最终对象，
parseResponse/normalizeResponse 零改动；服务端忽略 stream 位=JSON 原语义
回退）。本机证据=R10② SSE mock 双通道端到端（glm-look 子进程驱动；收割器纯函数向量已随 vecDs 删除——清理批次）；**真实端点
流式语义=真外呼窗口核验（原 B7 R1 载体已删——清理批次；现役核验面=设计岗
glm-look 首用窗口），未核验前勿断言根治**（同 evolve-b1 纪律）。

**故障形态**：后台派发长推理（5 分钟量级）被掐，服务端记 **499**
（context canceled——**客户端中断族，非服务端宕**；用户侧后台观察与
服务端日志互证）。链路=推理时长 > 网关 5 分钟**非流式窗口** → 网关
切断 → 后端在途调用记 499。

**根因双层**：①网关侧非流式窗口（服务侧约束）；②客户端侧 **undici
（global fetch）内建 headersTimeout≈300s 默认**——非流式长推理的
隐形杀手，306.3s 即 `TypeError: fetch failed`（本机 400s 延迟服务器
双臂探针：A 臂 global fetch 306.3s 即死；B 臂 node:http 直连 400s
全通，唯一超时=自设上限）。对照样本：成功派出 out≈9273 tok≈247s
——贴窗沿通过，窗口即硬顶。

**对策三层**：
1. **传输层**：弃 global fetch 改 **node:http(s) 直连**（postJson
   helper；undici 包在技能目录不可解析——动态 import 按模块位置走，
   故不采 setGlobalDispatcher 方案）；**signal 是唯一超时来源**，
   `CALL_TIMEOUT_MS=1_200_000`。退避/重试/解析语义零变化。
2. **输入层**：**审包体积=派发时效主变量**——同窗口内推理时长≈
   f(输入+输出预算)。审包 v4 实测 110KB→84KB：剔 registry 巨行/
   AGENTS 全文/methodology diff/变异 raw 附。
3. **输出层**：**产出预算硬约束**——简报输出段设 token 上限
   （补审先例 ≤4000）入任务书，防产出段撑长推理贴窗。

**分诊口诀**：499=客户端中断族——先分层（服务端/网关/客户端），
双臂探针定层，勿直断服务端宕。（流式化已由 B5 落地=本节首段；已登记残留仅
剩真实端点流式语义核验——登记于 RESIDUALS 触发器行 evolve-b1-transportresidual，
状态一律以待办清单为准，正文不复记防新旧两说并存——v2.0.1 修复批 D2 补还。原
句「流式化留技能层后续」系 B5 前旧结论，随批删除。）

**§6 补遗二：子代理失败接续 runbook**：

一、**死亡检测与归因（第一步必做）**：子代理无响应/失败返回/会话中断 →
先查日志归因再选处置（禁盲重试）：`node scripts/log-triage.mjs --hours 2 --health`
（技能根解析）。归因源=CLI 日志（子代理会话 model.network.* 事件）+
agents metadata（声明绑定/status/usage）。

二、**三类处置**（五类分诊收敛为三动作）：①额度类（429/403）=读进度落盘→
派另一源继任（双源岗互换；不同模型族岗按 org-config source_chain 递进）——承载切换不
放宽任务书与 DoD，事件入账；②窗口类（504/超长时延）=同源瘦身重派（同端点
共模切换承载源无效——处置=审包体积↓/产出预算硬约束/流式化）；③无工具岗中断
（纯包岗）=同包重跑（输入即全部状态）。其余类：传输层瞬时错=退避后同源
重派；配置错=停批修配置禁重试。

三、**继任者接续简报（固定三件）**：①已完成清单（来自进度文件/提交史，
逐项+证据指针）②剩余清单 ③上下文指针（进度文件路径/commit 范围/证据目录
——继任者第一动作=读指针恢复状态，并对已完成项证据文件做存在性核对，
缺=上报而非静默重跑）。

四、**分笔落盘纪律**（模型调用失败=子代理无法再汇报的等价实现）：写工具岗
每单元即时落盘（executor=分笔 commit；probe=进度文件回写）；只读岗=单交付物
短任务同包重跑（无进度文件——写通道会破坏只读墙）；纯包岗=同包重跑。

五、**简报层已知缺陷规避**：子代理 Bash 传参层 `>` 截断（已登记残留，宿主怪癖单源=references/10 §4）——含
`>` 的命令一律改脚本文件载体（先落 .js 再执行），修复前不派裸 `>` 命令。

**§6 补遗三：绑定岗通道异议以申报代替拒收（源事件=岗位实例自设「只收内联」墙拒收路径形态审包——与同岗位实例多次路径包先例冲突，裁决部建议成文）**：

绑定子代理岗位对派发包**通道形态**（内联全文/路径+授权等）有异议时，
唯一合法动作=向主控**申报**（异议理由+期望形态），由主控裁定重发或
维持——**禁岗位实例自行拒收、禁自设「只收 X」类通道墙**。要点：①输入
契约的墙在「喂什么」=主控派发面单源（输入边界协议），岗位实例对「怎么喂」
的异议走申报线、不入自决线；②自包含内联包仍是缺省正道（红旗「给
代码审查（岗）的包里含任何仓库访问信息」不变）——路径形态=主控明示授权才有
效，岗位实例据此申报≠错，错在拒收；③申报与裁定入账本（挂批号 runId）
可审计。
