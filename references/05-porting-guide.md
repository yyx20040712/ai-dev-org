# 05 · 移植指南（新项目怎么用/怎么裁）

> 合并自 WP methodology §7-§8 与 SY methodology §2 的适用边界，加裁剪矩阵。

## 1. 最小移植集（按优先级）

1. **宪法+门禁骨架**：把规则写进 CI/脚本（分层 import-linter、占位/魔法数字扫描、
   文件预算、乱码检查）；先有防线再写第一行业务代码；
2. **任务书+台账模板**：决策原文入账、需求唯一源（五层规约或 D 编号预裁决+白名单+DoD）；
3. **测试面双锁**：manifest sha256（跨平台真相）+ OS 只读（本地屏障）+
   （有工单制时）状态激活锁；测试变更=显式事件走受锁流程；
4. **双门审计通道**：隔离 diff 评审 + 实证对抗——两者不可互相替代；
5. **技能盘点开工纪律**：任何工作启动先清点环境技能（用/不用+理由落盘）+配置自查；
6. **交接协议**：台账追加式+交接书七件套+签署生效条件。

**不移植的**：具体数值/公式/业务库（领域资产非方法论）；单一项目的环境怪癖
（入各自项目的"环境事实"节，不进通用册）。

## 2. 裁剪矩阵（流程重量 × 任务类型）

| 任务特征 | 建议流程 | 理由 |
|---|---|---|
| 行为不可直觉验证/受锁面大/跨模块接缝多 | 全流程（基准 12 步+双门+返工上限） | 双门与工单化是重武器，正该用在这 |
| 事件驱动缺陷修复 | 压缩路径：取证→态空间→红→绿→双门 | 全流程性价比低 |
| 纯文档/单行修复/探索脚本 | 主控直做+轻量 diff 自查 | 派发无益（SY：按单元类型自然分流，不前置立法） |
| 数据密集批 | 数据专轨：起草-追认制+验算闭环+升版零扰动探针 | 专家时间是最稀缺资源 |
| CI/构建件变更 | 攒批+**逐 job 环境核查** | 三层漏检教训（WP-2） |
| 安全敏感（拼接/注入/出网） | 安全禁令否定式清单+穿越用例 DoD 必选项 | AU-1 Critical 教训 |

**项目规模裁剪**：≤1 周的脚本项目可只取 1/2/5 项（门禁+任务书+盘点）；
月级项目加 3/4/6；长期演进的核心系统全量+成本账本+不变量登记册。

## 3. 适用边界（何时不这样做）

- **重流程有成本**：三屋/双门每单元多花 token 与时长（SY 实测首单 ≈12.5M tokens/
  41.5 分钟——换来的是代码审查（岗）3W 全真缺陷拦截）；轻任务用重流程=纯浪费；
- **机检有误伤面**：blanket 禁令撞合法例外时回退为规约化不是失败而是校准；
- **状态机表不是免费的**：表前置针对"时序行为"，不是一切状态都要表格化
  （五模块正交坐标坍缩成单状态机反而更难审——SY ADR-0008）；
- **追认制有窗口期风险**：AI 起草→追认之间理论上可返工（缓冲：验算闭环+
  双源保守档+追认点显式化）；
- **返工依赖原实现者存活**：会话终止后换人重读报告，成本约 2 倍（实测可控）；
- **编排者单点**：主会话上下文超限时依赖台账/交接文档无损续作——文档群即为此设计。

## 4. 新项目落地 Checklist（首周）

**双形态（2026-09-10 起防线脚手架自带）**：先跑
`node <技能根>/scripts/init-defenses.mjs --target <项目根> --stack <npm-verify|pnpm-pygates|generic> [--yes]`
——一条命令落地下述防线日五项的骨架（宪法骨架+ORG-SEG 段带预算自检联动/
CI 骨架/门禁聚合入口/任务书模板（七段，惯称六段简报）/台账+org-delta 初始化/.gitignore 片段；
幂等可重跑，重跑=逐项 SKIP），再按下表**逐项核对**——脚手架≠防线齐装，
`[SKIP]` 行即缺口清单（已生成产物按 stack 有 verify 宽松/STRICT 双档）。

```
防线日（先于一切业务码；上命令已生成的项=核对，未生成项=手补）：
  [ ] git 基线+CI 骨架（哪怕只有 lint+test 两个 job）
  [ ] 宪法草稿（≤500 行：硬规则+否定式安全禁令+DoD+阅读顺序）
  [ ] 测试锁 manifest+只读属性脚本
  [ ] 门禁聚合入口（一键全查脚本/命令，CI 同口径）
  [ ] 任务书模板（七段，惯称六段简报）+台账文件（追加式）
  [ ] evidence 三子目录骨架（handoffs/＋close/＋session-logs/；指针=templates/evidence-skeleton.md）
首任务：
  [ ] 技能盘点落盘 → 冻结提取 → 任务书 → TDD（红实录→绿→变异红证）
  [ ] 双门派发模板就位 → 收口亲验（真退出码）→ 入账
  [ ] 第一次教训回流（哪怕只有一条：入教训库三段式）
```

**结项前防线自检（2026-09-14 优化批增，P0 三条）**——新项目落地后、
每次结项前逐项跑：
```
  [ ] node <技能根>/scripts/health-scan.mjs --project <项目根>   # RED=0 方可收口
  [ ] node <技能根>/scripts/check-hardcode.mjs                   # 供应商 live 事实零硬编码
  [ ] node <技能根>/scripts/health-scan.mjs --self-test           # 扫描器自检全过（向量数以实时输出为准，正文不落数字——A3）
  [ ] node <技能根>/scripts/check-hardcode.mjs --self-test        # 扫描器自检全过（同上）
  [ ] node <技能根>/scripts/regression.mjs --only R2,R4,R5        # 档案/记账/换源三面
```
判据速查：**截断的审计报告不算合格审计**（health-scan ④ RED，见 02 §10）；
**演练行不得参与待补登记判定**（源头写 `mocked:true`）；**声明必须有机检**
（06 §0 零硬编码声明 ↔ check-hardcode）；**白名单/豁免登记措辞=授权面
须精确**（文件+行级锚定，禁「仅…一行级」类含糊上限表述——登记面大于
实际改动=豁免外溢面；先例=evolve 批 plan 白名单措辞失准，终审 P2-②）。

## 5. 与两项目源文档的关系

- 本套是**整合视图**（整合基准 2026-08-27；其后演进以本件修订记与
  08 §4 体检为准——基准日≠最新态）；两项目各自的宪法/方法论是其领域的
  **单一真相源**——冲突时以仓库内文档为准；
- 移植时优先抄各自仓库的模板实物（WP `briefs/task-M3c-brief.md` 简报范式、
  `scripts/run_gates.py` 门禁实现；SY `docs/methodology.md` §4 派发模板三件、
  `scripts/check-locks.mjs`/`check-tickets.mjs` 实现）——模板偏差=返工主要来源，
  勿凭记忆重写；
- 迁移场景的专项清单见环境层快照（仓外历史区文件，不随本技能分享包分发）与
  两项目各自的 MIGRATION.md / DEV-SETUP.md（项目层）。

## 6. 差异回灌协议（ai-dev-org v1——首适配场经验回流通道）

- 首适配场（及一切后续适配项目）在项目根 `.zcode/org-delta.jsonl`
  逐批次组/逐票追加一行：`{date, ticket, delta, suggestion}`（delta=
  环境差异/流程摩擦/机检误伤的实际描述，suggestion=建议去向：
  本指南某节/角色档案/org-config/教训库）。
- 技能下一版本发布前由**主控**汇总该文件并终裁改写范围；改写案可交
  规划岗以设计书形态拟稿（drafter 只拟不改写——职责边界照 07 §1），
  主控终裁后落地；账本记 `event=porting-delta`。
- **必记触发线**：①环境差异（绑定子代理可用性/端点形态/源序变化——派发器已退役 2026-10-03）；
  ②流程摩擦（模板偏差导致返工）③机检误伤（强制项撞合法例外）。
  纯项目怪癖不回灌（入各项目宪法环境事实节）。
- Synapse 首适配首行示例见该仓库 `.zcode/org-delta.jsonl`（2026-09-10
  ORG-SEG 插入+双派发器并存期）。
