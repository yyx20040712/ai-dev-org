# 02 · 循环管道（一个批次怎么走完）

> 统一视图：WaterPrint 管道 v2.1 × Synapse 三屋模式（ADR-0017）的同构合并。
> 差异处以【WP】/【SY】标注；无标注=两项目通用。

## 1. 角色与职权

| 角色 | WP 承载 | SY 承载 | 职责 | 禁止事项 |
|---|---|---|---|---|
| **编排者** | 总控（主会话） | 主控（会话） | 任务拆解/Ruling/简报或工单预裁决/派发/终裁亲验/台账或 registry/交接 | 不写实现码；不跳过审计；决策原文入账 |
| **冻结提取** | E（Explore 只读） | ——（主控自读） | 冻结上下文：签名/占位消息/规格原文逐字 | 不写文件；不确定标"需裁决" |
| **实现者** | I（general-purpose） | 实现者子代理 | 按任务书 TDD 实现+分笔 commit+报告 | 派子代理；越白名单；改锁定区；碰 git/registry【SY】；ruff 不跑就 commit【WP】 |
| **门一（隔离/对抗）** | D 一审（code-reviewer，无 Bash） | 门一孙代理（只读+唯一可写审计档） | 纯 diff 包评审：断言弱化/范围/规格符合性/报告诚实性 | 接触仓库跑命令【WP】；臆测包外事实 |
| **门二（实证/终审）** | A 二审（general-purpose） | 门二孙代理 | 仓库实证：逐条裁决 CONFIRMED/REJECTED/ESCALATED+独立复算+亲跑 | 预设立场；只审不跑 |
| **领域专家（用户）** | 追认面批量裁定 | plan 门逐张过票面+验收视检 | 数据追认/负面清单/规格冲突的终裁 | ——（不可下放） |

**上下文治理**：主会话只留裁决与结论，全文材料下沉各代理产出物（报告/审计包）
——长会话不失焦的根基【WP】；分级阅读+指针化+摩擦常量化【SY】（见 01·B5）。

## 2. 单批次流水线（基准 12 步）

```
1. [编排者] 开工体检：工作树清洁+HEAD 基线+门禁全绿+全量不回退——异常即停
2. [编排者] 技能盘点：枚举当前环境可用技能，逐项标"用/不用+理由"，落盘后才许动手
3. [编排者] （需探索时）冻结提取 → 任务书（简报/工单）：预裁决编号+全签名+白名单
           +探针清单+DoD+commit 顺序；记录 BASE 提交号
4. [实现者] TDD：红（实录）→绿→变异红证→探针（临时脚本用后删）
           →分笔中文 commit（每笔前 lint）→报告（DONE/DONE_WITH_CONCERNS/
           NEEDS_CONTEXT/BLOCKED + 自裁申报）
5. [编排者] 亲验（不信自报）：git 终态+门禁+全量+lint → 生成审计包
6. [门一]   隔离评审：逐条 [B|W|N] + file:line 证据 + 断言弱化判定 → 审计报告
7. [门二]   实证终审：逐条裁决+独立复算+亲跑矩阵 → 裁决报告（含回炉建议）
8. [编排者] 回炉：按裁决逐项下发原实现者；一轮一回审（定点 ADDRESSED+新破坏扫描）
           —— 回炉有上限（WP R≤5/R≤3 续用原实现者；SY ≤2 超限终止留人）
9. [编排者] 终裁收口：亲验全绿（真退出码）→ final 报告 → 台账/registry 翻状态
           → 显式列文件提交（受锁面带 [locked-change] 尾注）
10.[编排者] push → CI 核查（消费 job 全绿；有触发延迟窗口的先等复查窗口）
11.[编排者] 成本入账【SY】：子代理 token/时长分列（实现者/门一/门二）
12.元循环：教训三条入账路径——台账教训条目 → 教训库 → 可机器化者升格质量门条款
```

**步骤 2 的宪法级地位**：未完成技能盘点不得开工。判据：与任务相关的工程技能
（系统化调试/TDD/完成前验证/子代理开发等）默认"用"；标"不用"必须给具体理由。
同源事故【SY】：未加载工程技能裸手搭审计流水线+模型思考等级配错→整场裁决作废。
配置自查随清点一并做（等级配错的模型签发的一切裁决视为无效）；含模型路由自查
（各角色模型/供应商符合 §8 路由表，Kimi 主源可用性确认，GLM 体验套餐可用性盘点）。

## 3. 批次类型与节奏

| 类型 | 流程要点 | 先例 |
|---|---|---|
| **实现批** | 基准 12 步 | WP T7/M1/M2 系 |
| **数据批** | 起草-追认制：表起草+系数升版+验算闭环探针（0 失败实录）→工程评审→独立复算 | WP M2a1/M2b1 |
| **表实合批** | 数据前置一笔 commit 后逐单元实现（流程成熟且单元数≤4 时用） | WP M2c/M3c |
| **工单化战役**【SY】 | plan 门（票面终审先于实现）→逐单 TDD+双门+一单元一提交+禁同批多单→收官（e2e 扩展+ROADMAP/不变量回写+战役报告） | SY P7-A/B/C 三役 |
| **工程攒批** | 小而确定项合并；任务书可精简但 CI 相关件必附 job 环境核查 | WP ENG1 |
| **文档/制度批** | Ruling 落账→宪法/文档同步（涉仓库文件走轻量双审） | WP 数据策略 v2 |
| **压缩路径** | 事件驱动缺陷单元：取证→态空间→红→绿→双门（不必全流程） | SY 适用边界条款 |

**战役制交付节奏**【SY】：收官即回写（ROADMAP ✅ 与基线快照同步），不留"事后补文档"的窗口；
战役报告是知识回流枢纽（教训节→下任交接书→有普遍性的升格宪法/方法论）。

## 4. 任务书（简报/工单）必备要素

固定六段，缺一段=任务书不合格【SY 试点实证：模板偏差=回炉主要来源】。
（2026-09-14 P1-1 增第 7 项「运行时可观察性」——见下第 7 条。）

1. **身份与禁令**：执行者身份/领单号/禁令清单（禁 git/registry/禁新依赖…）
2. **必读序**：宪法→票面/简报（=完整任务书）→ADR 母本→**先例池文件清单化**
   （逐文件列路径+看什么，禁写"相关先例自寻"）
3. **预裁决**：票面范围内的工程歧义逐条给依据（执行者不再自裁这些点）
4. **纪律**：TDD 红→绿→变异红证；测试命令收敛口径；真退出码落盘
   （`echo exit=$? >> 日志`）；卡点=BLOCKED 停手不自裁
5. **基线数字**：verify 用例数/locks 数——执行者自检参照（防"数字对不上=环境配错硬闯"）
6. **报告契约**：全文落审计档（实现摘要/文件清单/红证/测试证据/locks 实录/
   **自裁申报**含删减面 diff 自查/疑虑）；回复五行内
7. **运行时可观察性**（2026-09-14 P1-1）：每个新行为须回答"上线后我怎么
   看到它在正常工作"，落成具体形态（日志字段/指标/健康检查/断言式告警
   之一）；答不出=该行为不可验证，停手上报。理由=A1 的"合入前现形"覆盖
   不到逃逸到线上的错误，此为运行时的最小落点。

**白名单机制**【WP】：架构层逐文件列"新建/修改/禁改"三态；禁改项里顶格文件要显式点名
（如 dimensions.py 500/500 顶格——新维度若需=停报由总控裁拆分批）。
白名单是护栏不是障碍：修复面超白名单时执行者停手上报、编排者扩权（有先例=正确执行）。

## 5. 回炉（修复轮）规则

- **触发**：门二必改项（CONFIRMED 级）或 CI 事故；
- **下发**：编排者逐项裁定+必要时扩白名单，原实现者续命（上下文仍在，修复成本最低）；
- **上限**：【WP】≤5 轮，R≤3 续用原实现者，超限换人重读报告（成本约 2 倍，实测可控）；
  【SY】≤2 轮，超限终止留人升级用户——每轮修复引入新修复面时，回归用例与 diff 净增量化是强制止损器（UNDO-01 七轮振荡链教训）；
- **验证**：每项修复带探针实录+全量不回退；纯注记级走轻量验证（子集+门禁）；
- **顺手闭合**：≤5 行的 Minor 允许随轮回（lint 前缀/注释笔误类）。

## 6. 数据治理专轨（起草—追认制）

适用：领域数据量大、专家时间稀缺。

```
AI 起草（限定可信源白名单——WP=国标+核心手册两类，标记泛滥=标记失效）
  → 表内验算闭环（脚本重算公式链 vs 期望值，0 失败才出手，实录进报告）
  → 双审工程评审（找"改哪个数都对不上"的隐性矛盾）
  → 领域专家批量追认/抽验（显式清单化：构造假定/口径选择/贴限敏感性逐条列出）
  → 追认后锁定（签字栏回写+台账 Ruling 记账+测试面锁定）
  → 改定项走数据包升版批（旧键零扰动探针照跑）
```

**两方向不可自洽的口径必须暴露**（紫外渠道"1 用 1 备"字面 vs 双渠计算口径矛盾先例）
——审计门的职责就是找出这类矛盾交所有者裁定，不许按字面硬算也不许悄悄选边。

## 7. 交接（取代制）

- **台账条目模板**：Task X: complete（门一结论→门二裁决→回炉→终裁指引）
  + commit 清单+终态数字+移交挂账；
- **断点即记**：用户暂停/代理终止/push 阻塞都记；
- **交接书七件套**【WP】：体检口径/真相/管道/授权/挂账/索引/开工第一句；
  【SY】交接书=下一棒自包含开工指令（含分级阅读 §1 指针+成本账本行）；
- 交接生效条件：接手人完成开工体检并**签署**（体检报告落盘为证）。

## 8. 模型路由与额度纪律（2026-09 环境新增）

> **条款性质**：由 2026-09 模型订阅变更驱动的配置性条款（GLM 最高档套餐
> GLM5.3+GLM5.3flash、Kimi K3 企业版），非两项目实证条款——实证锚点待首场战役
> 回填；此前按流程性规则执行，不升格硬门禁。**2026-09-02 修订（Ruling，当日
> 澄清）**：deepseek v4 flash=套餐外按量价格——实现面禁用、审计面放行（§8.5）。

### 8.1 额度事实与路由总则

- GLM5.3+GLM5.3flash 为额度基准；Kimi K3 可用体感额度≈GLM 的 1/10——**稀缺额度
  只投两处：门一异构对抗＋路线级设计拟定（§8.6）**；deepseek v4 flash=第二审计
  工力——套餐外按量价格，2026-09-02 Ruling：实现面禁用、审计面放行（§8.5，
  路线级审核位同属审计面）。
- 派发子代理必须显式指定模型/供应商，禁止静默继承默认（等级配错裁决无效条款照用）。
- 实现者与审查者异源时盲区不重叠——这是双门制度在多模型环境下的加强形态，
  与路线级设计拟定（§8.6）同为 Kimi 额度两大投放面。

| 角色 | 默认模型 | 理由 |
|---|---|---|
| 编排者 | GLM5.3 | 拆解/裁决/终裁亲验是判断力密集环节，不降档 |
| 实现者 | GLM5.3flash（默认）；并行批或限流→串行降批等待（不换套餐外源） | 高吞吐环节用廉价快档；同批实现者不混模型（报告口径一致） |
| 门一 | **Kimi K3**（供应商固定顺序：Kimi→zipoo） | 与实现者异源=真对抗 |
| 门二 | deepseek v4 flash / GLM5.3flash（与同批实现者异构优先） | 复算要"独立"，先做到"异源"——deepseek 审计面放行 |
| 拟定者（路线级，§8.6） | **Kimi K3**（Kimi→zipoo） | 长上下文 1M+重推理适合架构设计书拟定 |
| 审核者（路线级，§8.6） | deepseek v4 flash | 异构挑刺——审计面放行条款照用 |

### 8.2 换源与降级状态机

```
派发门一 → 主源"Kimi"可用？
 ├─ 可用 → 走 Kimi（不得主动跳过主源改用 zipoo）
 ├─ 额度耗尽/限流/配额错误 → 任务书原样改派 zipoo
 │    （任务书与 DoD 不许因换源放宽；换源事件+批次号入台账）
 └─ 双源皆尽 → 门一降 GLM5.3 兜底，台账记"同源审计欠账"
      → 下一关键批优先补还异构审计；连续两个关键批未补还→升级用户裁决
```

落地（2026-09-02，WaterPrint 实装）：ds_review.py v2.7 自动执行本状态机——
源序 Kimi→Kimi 备源→deepseek 审计兜底（Ruling 当日澄清：审计面放行）→源尽
记欠账回退 code-reviewer；换源/欠账/用量事件写 `reports/model-routing-log.jsonl`
并标注于审计报告头；派发器内 GLM 兜底须 OpenAI 兼容端点条目（builtin
anthropic 格式未适配）。

### 8.3 配给红线

- **Kimi 必保批次**：路线级设计拟定（§8.6）、受锁面修改、安全面、跨模块接缝、
  数据批/迁移、回炉第二轮起、新依赖引入。
- **可省批次**：≤3 文件小批、纯文档/注记批、工程攒批非 CI 件——门一降 GLM5.3
  并在台账标注（配给内降级，非欠账）。
- **成本入账（步骤 11）按"模型×供应商×套餐"分列**——额度是一等公民资源，烧在哪必须能指认。
- 关键批次（受锁面/安全/数据批）开工前随步骤 2 配置自查确认主会话在 GLM5.3 档；
  flash 档主会话可编排普通批。

### 8.4 体验套餐优先（2026-09 补充）

- **开工盘点**：步骤 2 配置自查一并盘点套餐池——正式套餐（GLM 最高档/Kimi
  企业版；deepseek=套餐外·审计面放行/实现面禁用，盘点防误用）+ 当前可用的
  GLM 体验套餐，逐项记档位/时效/剩余量/能力覆盖。
- **发现即优先**：发现 GLM 体验套餐（如 GLM5.3flash 体验包）即优先消费——同档位
  先烧体验再烧主力；体验额度易逝、闲置到期=纯浪费，"优先"既省正式额度也免浪费。
- **多模态任务→GLM5.3flash 体验套餐优先**：截图审查/图像理解/验收视检等多模态
  环节默认路由 flash 档体验套餐；无体验套餐则走 flash 主力，不占 GLM5.3/Kimi 额度；
  涉及关键裁决的多模态证据仍按门二条款亲验复核。
- **不降档护栏**：判断力密集环节（编排终裁/关键批门一）不因有体验额度而降档——
  体验优先只适用于体验套餐能力覆盖得住的环节。
- **耗尽回落**：体验套餐额度耗尽/过期→按 §8.1 路由表回落正式套餐；这是额度调度，
  **不记换源事件**（换源状态机仅管 Kimi 主备源）。
- **入账**：成本按"模型×供应商×套餐"分列——体验额度烧在哪同样必须能指认。

### 8.5 deepseek 分面放行（Ruling 2026-09-02 当日澄清）

- 用户裁决原文口径：「代码实现不用 deepseek 写；审计工作让它分析是合适的」。
- **实现面禁用**：实现者一律 GLM5.3flash（限流→串行降批等待，不换套餐外源；
  备援位永久移除）。
- **审计面放行**：门一兜底层（Kimi 双源之后、agent 回退之前）+门二异构位
  （deepseek/GLM5.3flash 与实现者异构优先）。
- 套餐外计价——仅审计环节使用、用量受控；成本按"模型×供应商×套餐"入账
  （门一派发器流水账自动分列）。

### 8.6 架构/技术路线三段通道（Ruling 2026-09-02 第四次；对齐 06·v1.1）

- **适用面**：架构设计/技术选型/跨模块重构路线/性能优化方案等"路线级"决策——
  即任务书（步骤 3）需预裁决路线级歧义的批次与 ADR 级决策。单函数级局部优化
  不走此通道（编排者直裁，省 Kimi 额度）。
- **三段链条**：
  0. **社区实践调研前置（用户 Ruling 2026-09-10）**：较大模块的技术
     路线选择，主控在派发拟定前先做**社区实践调研**——调研社区内
     技术大佬/知名开源项目/权威团队对同类模块的选型与结论（来源=
     公开文档/源码/技术报告，可用 WebSearch），产出「候选路线×各家
     选择×理由摘录」清单，随任务包提供给拟定者（Kimi）作参考输入
     ——**不闭门造车即可**，不要求穷尽；调研来源入设计书附录可追溯。
  1. **Kimi 拟定**设计书：候选路线≥2+逐项权衡（复杂度/风险/迁移成本/额度成本）
     ——长上下文+重推理适合架构拟定；主源 Kimi，耗尽/限流按 §8.2 源序换源
     （DoD 不放宽）；双源皆尽→编排者自拟并记"拟定同源"事件（欠账语义同 §8.2）。
  2. **deepseek 对抗审核**：异构挑刺——风险点/隐性成本/被遗漏的第三方案/与

  3. **GLM5.3 主控终裁+指挥实现**：唯一终裁权——合并拟定与审核意见定案
     （负面清单/新依赖/规格冲突仍留用户），随后按管道派发实现者落地。
- **利益分离**：拟定者不终裁、审核者不改写、终裁者不跳审自裁设计——设计与

- **与双门关系**：设计阶段的异构对抗前移——实现完成后的门一/门二照走，
  方案过三段通道不免实现审计。

## 10. 烤验机关（对抗拷问的流程化——2026-09-10 W4）

> 烤验文化：对抗拷问不是刁难而是义务——审查者的工作是找茬，找不出
> 茬=没尽责；执行者的工作是假设明示，把没验证的判断暴露给拷问者。
> 本节把该文化从「纪律要求」升级为「流程机关」（可机检/可扫描）。

- **烤验触发表**（SKILL.md 同名节）：批次类型→强制对抗位映射；派发前
  自检三问（命中位/源异构性/欠账补还）——任一未过不得派发收口。
- **假设位明示**：主控简报/任务书中的关键假设（对用户意图的理解/
  对既有行为的判断/对环境事实的认定）须逐条标注「假设：…」并列入
  派发包请对抗位优先拷问；审查报告须含「假设拷问」节——假设未被
  拷问=烤验未过。假设被证伪=回炉触发条件之一（§5）。
  **机检锚（W5 审双源同款意见，可判口径）**：①派发包头部设
  `assumptions:` 清单节（逐条编号，无假设须显式写「无」——空节≠
  无节）；②审查报告「假设拷问」节逐条给 verdict=证伪/未证伪+依据；
  ③主控收口自检=核对①②两结构存在且条目数一致（结构级机检；
  内容质量仍属人工对抗位，如实注记此边界——账本 schema 不含假设
  字段，全自动化暂不可达）。
- **红旗自动扫描**（`scripts/health-scan.mjs`，纯本地零派发；收口前
  必跑，RED=0 方可收口）：
  - ①欠账未还（RED）：账本 exhaust 行后同项目无补还 ok 行——06 §4
    「连续两个关键批未补还=升级用户」的机检前置；**2026-09-14 起
    跳过 `mocked:true` 行与 `os.tmpdir()` 前缀的临时演练项目**（P0-1：
    演练行不参与欠账判定，"可人工甄别"不得替代机检）；
  - ④审计产出截断（RED，2026-09-14 P0-2/W-3）：audit_surface 岗（从
