## 2. 单批次流水线（基准 12 步）

```
1. [编排者] 开工体检：工作树清洁+HEAD 基线+门禁全绿+全量不回退——异常即停
2. [编排者] 技能盘点：枚举当前环境可用技能，逐项标"用/不用+理由"，落盘后才许动手
3. [编排者] （需探索时）冻结提取 → 任务书（简报/工单）：预裁决编号+全签名+白名单
           +探针清单+DoD+commit 顺序；记录 BASE 提交号
4. [实现者] TDD：红（实录）→绿→变异红证→探针（临时脚本用后删）
           →分笔中文 commit（每笔前 lint）→报告（DONE/DONE_WITH_CONCERNS/
           NEEDS_CONTEXT/BLOCKED + 自裁申报）
5. [编排者] 亲验（不信自报）：git 终态+门禁+全量+lint → 生成审计包
6. [门一]   隔离评审：逐条 [B|W|N] + file:line 证据 + 断言弱化判定 → 审计报告
7. [门二]   实证终审：逐条裁决+独立复算+亲跑矩阵 → 裁决报告（含回炉建议）
8. [编排者] 回炉：按裁决逐项下发原实现者；一轮一回审（定点 ADDRESSED+新破坏扫描）
           —— 回炉有上限（WP R≤5/R≤3 续用原实现者；SY ≤2 超限终止留人；
           ai-dev-org 新项目默认口径=本件 §9 适配注记）
9. [编排者] 终裁收口：亲验全绿（真退出码）→ final 报告 → 台账/registry 翻状态
           → 显式列文件提交（受锁面带 [locked-change] 尾注）
10.[编排者] push → CI 核查（消费 job 全绿；有触发延迟窗口的先等复查窗口）
11.[编排者] 成本入账【SY】：子代理 token/时长分列（实现者/门一/门二）
12.元循环：教训三条入账路径——台账教训条目 → 教训库 → 可机器化者升格质量门条款
```

**步骤 2 的宪法级地位**：未完成技能盘点不得开工。判据：与任务相关的工程技能
（系统化调试/TDD/完成前验证/子代理开发等）默认"用"；标"不用"必须给具体理由。
同源事故【SY】：未加载工程技能裸手搭审计流水线+模型思考等级配错→整场裁决作废。
配置自查随清点一并做（等级配错=与声明意图不符的**未申报**错配，其签发的一切裁决视为无效；已声明意图档位+欠账行的随宿主形态=合法降档记账非配错——06 §6/E3 桥接）；含模型路由自查
（各角色模型/供应商符合 §8 路由表，Kimi 主源可用性确认，GLM 体验套餐可用性盘点）。

## 3. 批次类型与节奏

| 类型 | 流程要点 | 先例 |
|---|---|---|

| **工单化战役**【SY】 | plan 门（票面终审先于实现）→逐单 TDD+双门+一单元一提交+禁同批多单→收官（e2e 扩展+ROADMAP/不变量回写+战役报告） | SY P7-A/B/C 三役 |
| **工程攒批** | 小而确定项合并；任务书可精简但 CI 相关件必附 job 环境核查 | WP ENG1 |
| **文档/制度批** | Ruling 落账→宪法/文档同步（涉仓库文件走轻量双审） | WP 数据策略 v2 |
| **压缩路径** | 事件驱动缺陷单元：取证→态空间→红→绿→双门（不必全流程） | SY 适用边界条款 |

**战役制交付节奏**【SY】：收官即回写（ROADMAP ✅ 与基线快照同步），不留"事后补文档"的窗口；
战役报告是知识回流枢纽（教训节→下任交接书→有普遍性的升格宪法/方法论）。

**审级统一口径（[B|W|N] 定义单源——两角色 DoD 均为指针，勿在他处复写定义）**：
B=阻断实施（不清不得前进）／W=应修（批内修或显式登记残留）／N=提示。
VERDICT 词表按岗分设：门一=`PASS|FAIL`；auditor=`放行|有条件放行|返工`
（门一/auditor 两套词表的统一=残留册 findings-parser 一并处置）；门二逐条裁决词表=
`CONFIRMED|REJECTED|ESCALATED`（2026-09-29 自本件 §1 表职责列收编——
§1 表收敛后本节为其单源；门二系会话内岗、无 DoD 尾栏契约，不入
findings-parser 统一面）。

## 4. 任务书（简报/工单）必备要素

固定七段（1-6 段惯称「六段简报」），缺一段=任务书不合格【SY 试点实证：
模板偏差=回炉主要来源】；第 7 项「运行时可观察性」=2026-09-14 P1-1 增
（evolve 批 b8 单源根治：删除原括注补丁句式，语义并入本句）。

1. **身份与禁令**：执行者身份/领单号/禁令清单（禁 git/registry/禁新依赖…）
2. **必读序**：宪法→票面/简报（=完整任务书）→ADR 母本→**先例池文件清单化**
   （逐文件列路径+看什么，禁写"相关先例自寻"）
3. **预裁决**：票面范围内的工程歧义逐条给依据（执行者不再自裁这些点）
4. **纪律**：TDD 红→绿→变异红证；测试命令收敛口径；真退出码落盘
   （`echo exit=$? >> 日志`）；卡点=BLOCKED 停手不自裁
5. **基线数字**：verify 用例数/locks 数——执行者自检参照（防"数字对不上=环境配错硬闯"）
6. **报告契约**：全文落审计档（实现摘要/文件清单/红证/测试证据/locks 实录/
   **自裁申报**含删减面 diff 自查/疑虑）；回复五行内
7. **运行时可观察性**（2026-09-14 P1-1）：每个新行为须回答"上线后我怎么
   看到它在正常工作"，落成具体形态（日志字段/指标/健康检查/断言式告警
   之一）；答不出=该行为不可验证，停手上报。理由=A1 的"合入前现形"覆盖
   不到逃逸到线上的错误，此为运行时的最小落点。

**白名单机制**【WP】：架构层逐文件列"新建/修改/禁改"三态；禁改项里顶格文件要显式点名
（如 dimensions.py 500/500 顶格——新维度若需=停报由总控裁拆分批）。
白名单是护栏不是障碍：修复面超白名单时执行者停手上报、编排者扩权（有先例=正确执行）。
**任务书一致性自检（2026-10-05 用户裁决回落，writeback-2a6-8）**：任务书
落笔后三方对账——白名单枚举 ↔ §1 禁令括注 ↔ §3 预裁决 D 项（D 已授权
而白名单/枚举漏列=枚举缺口；反向超列〔白名单超出 D 授权面〕与白名单
↔禁令括注互斥〔同文件既列改动又列禁触〕同为缺口——对账为双向四查，
先例=2A5 global.css 漏列〔实现者自裁申报+主控追认〕）；数字类事实
（行数/键数/用例数）标实测来源，禁转抄源注释
或记忆值（反例=2A6「顶层 10 键」/2A8「33 行」——均被实现者/门一兜出，
每例=一轮额外对抗成本）。

**任务书机检（2026-10-22 L5 批立）**：任务书落笔后、派发前必跑
`node scripts/check-taskbook.mjs <任务书路径> --root <项目仓根> --root <技能仓根> --strict`。
FAIL 一律不得派发；WARN 须逐条处置或登记理由。仓外/历史路径引用须用 `tb-ignore`
行级标记，未标记的 T1 命中在 `--strict` 下阻断。行号引用一律写成
`path:NN「原文片段」` 形态（机检逐字核对第 NN 行含该片段）；单一「第 N 行」
表述不再作为可核验引用，出现即按未核验处理。先例=P7 任务书三类缺陷
（逐字规格与零命中判据互斥、行号差 1、脚本净树要求与禁 git 互斥），
前两类属本工具可机检面，第三类仍须人工对账。

机检之外，任务书派发前还须经审核岗审核（D21）：交 `ops-reviewer-yyx-max`
（默认席位，D25；任务书由主控撰写、主控承载于 deepseek 族，审核须异族），
审包自包含（任务书全文+所引原文片段），不含仓库访问授权，输出 VERDICT 与
[B/W/N]。机检管内部不一致，审核管规格本身错或缺（验收判据不可执行/要求了
做不到的动作/关键假设未标注）。审核 FAIL 须改后重交，两轮不过=停手交用户。

每次审核补记账本一行，`runId` 命名 `<批次>-tb-review`；行字段依
`references/02` §9 账本 schema（此处不复写字段清单，防双源），PASS 与 FAIL
都记（D24）。该要求当前靠人工纪律执行，不设机检门禁。

## 5. 回炉（修复轮）规则

- **触发**：门二必改项（CONFIRMED 级）或 CI 事故；
- **下发**：编排者逐项裁定+必要时扩白名单，原实现者续命（上下文仍在，修复成本最低）；
- **上限**：【WP】≤5 轮，R≤3 续用原实现者，超限换人重读报告（成本约 2 倍，实测可控）；
  【SY】≤2 轮，超限终止留人升级用户——每轮修复引入新修复面时，回归用例与 diff 净增量化是强制止损器（UNDO-01 七轮振荡链教训）；
  ai-dev-org 新项目宪法未声明时取严者（默认口径单源=本件 §9）；
- **验证**：每项修复带探针实录+全量不回退；纯注记级走轻量验证（子集+门禁）；
- **分级收口（2026-10-05 用户裁决回落，writeback-2a6-8）**：回炉轮处置项
  全为 N 级（建议/记档）时=主控亲笔+全机检矩阵复跑+门二行为佐证即可
  收口，免门一复审；轮内含任何 W/B 级项仍须门一复审（「已审面修改=
  随批重过」不变）。对冲=免审处置逐条落批档（finding→处置→证据三
  栏）+health-scan 可审计——防「W 降格 N」自降级。N 级处置若触及
  已审面的仓内文件=该面仍随批重过（免审口径仅覆盖纯批档处置与记档
  ——「改了就要再审」为全局不变量，不随分级收口豁免）。
- **顺手闭合**：≤5 行的 Minor 允许随轮回（lint 前缀/注释笔误类）。
- **审核岗复用（D26，2026-10-22 用户裁决）**：同一批次内多轮返工
  （r1、r2…）的审核，复用首次审核的同一子代理实例（续接同一 `agentId`），
  不每轮新建——上下文仍在，缓存命中提高，成本最低。四条边界：
  ①范围限同一批次、同一审查对象的连续轮次，跨批次不复用（对象不同，
  跨批复用会引入污染）；②任务书审核与实现审核各自独立实例，互不复用
  （两者对象与阶段不同）；③复用不等于凭记忆——每轮仍须核对当轮改动，
  上一轮结论只作待验证项、不作前提，发现「上一轮说改了但实际没改」照
  常报；④上下文接近上限时新建实例，并在审核报告中申明「新建及理由」。
  与实现岗「原实现者续命」同源：省的是一遍重建上下文，不省核验强度。

## 6. 数据治理专轨（起草—追认制）

适用：领域数据量大、专家时间稀缺。

```
AI 起草（限定可信源白名单——WP=国标+核心手册两类，标记泛滥=标记失效）
  → 表内验算闭环（脚本重算公式链 vs 期望值，0 失败才出手，实录进报告）
  → 双审工程评审（找"改哪个数都对不上"的隐性矛盾）
  → 领域专家批量追认/抽验（显式清单化：构造假定/口径选择/贴限敏感性逐条列出）
  → 追认后锁定（签字栏回写+台账 Ruling 记账+测试面锁定）
  → 改定项走数据包升版批（旧键零扰动探针照跑）
```

**两方向不可自洽的口径必须暴露**（紫外渠道"1 用 1 备"字面 vs 双渠计算口径矛盾先例）
——审计门的职责就是找出这类矛盾交所有者裁定，不许按字面硬算也不许悄悄选边。

  上句与体感注记=企业版时代口径，对真稀缺源〔链首〕仍适用；kimi 现役承载源
  配额充裕≈主力之半，稀缺投放前提对其失效——其投放面=门一异构对抗＋路线级
  设计拟定＋前端设计稿拟定〔新增，经拟定者通道，派发显式指定充裕承载源、

  工力——套餐外按量价格，2026-09-02 Ruling：实现面禁用、审计面放行（§8.5，

  「显式指定」合法形态（枚举与随宿主形态的 E3 记账要件）**单源=06 §2 铁律 1**，
